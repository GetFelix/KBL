# Changelog

## Unreleased

## [0.2.1] - 2026-11-19

- Upgrading from 0.2.0: upgrade forward only. Logs created or written by 0.2.1 use log format 25 and cannot be opened by 0.2.0. A new work log starts at format 25; a log that already has records stays at its format until a person posts `format_raised` (see [upgrades](docs/upgrades.md)), and the raise cannot be undone, so back it up first. To start fresh with this release, check out `v0.2.1` and run `KBL_IMAGE_TAG=v0.2.1 dev/quickstart.sh`.
- Added: A triage policy accepts routine triage without a person. Set `KBL_TRIAGE_POLICY_FILE` to a JSON file of rules over what triage recorded (`tiers`, `areas`, `deny_areas`, `types`, `sizes`, `deny_needs`); when a finished, plain triage matches a rule the tracker writes `accepted` as itself with the rule's name in `admitted_by`, and everything else stays in Needs you. A person can take a policy acceptance back from the dashboard (`undo_admission`, `POST /v1/work/proposals/undo-admission`), which returns the root to Triage and keeps the policy off it. The dashboard shows "Admitted by policy <rule>" on the item and in its history. This is log format 25, so raise the format before the policy runs; with no policy file a person accepts each triage.
- Added: A supervise profile can set `git_identity = { name, email }`, which `kbl-mcp` turns into the four `GIT_AUTHOR_*` and `GIT_COMMITTER_*` variables for that worker (`set_env` wins if both name one). The email is checked when the config loads. The profile docs show how to turn off Claude Code's `Co-Authored-By` trailer and PR footer, which fail CLA checks.
- Changed: Dashboard: the board keeps its column widths when the item panel is open (the panel floats over the right edge), phone filters fold behind one Filters button, Save view is a bordered button, a stopped dashboard says "Your session ended." with the code in a details line, the Stop button lines up in the phone worker block, and a finished or stopped worker shows nothing for an unrecorded vendor or model and "Nothing held" instead of "None" (#465, #466, #467, #468, #469, #470).
  The item panel leads with the upstream reference and keeps the item id beside it, a pull request address reads owner/repo#N, child work is one compact row (kind, state, holder) on the board, in the list and in the panel, and the stage no longer shows a stale triage state next to a linked fix.
- Changed: The stored fold results in `wasm/golden` change: `format_25` is new, and `every_record` now shows `policy_held` on the root its `reopened` record returns to Triage, because a reopened root waits for a person and the triage policy leaves it alone.
- Changed: Admitted roots now wait for their triage to be accepted, by a person or by a triage policy, before any agent is handed their fix. Admit mode no longer writes `accepted` for a rule that runs triage, so `work_next` and `work_peek` show triage and augment first. This applies at every log format, so it is a behaviour change on upgrade: to keep the old auto-accept for issues that are already well specified, set `"triage": "skip"` on the rule. The intake rule's tier is kept as the last choice: an accept takes a person's tier, then triage's, then the rule's (`intake_tier`, format 25).
- Changed: From format 25, finishing a fix cancels triage and augment items nobody holds and that have no recorded work instead of refusing with `open_children`. Any other open child still blocks it, and the refusal now names each one and who holds it.
- Fixed: The dev scripts (`dev/ingest.mjs`, `dev/connect.mjs`, `dev/agents.mjs`) find `kbl-ingest` and `kbl-mcp` on `PATH`, after the flag, the environment variable, the build directories, `~/.kbl/bin` and `dev/state/bin`, and the not-found error lists every place. `dev/ingest.mjs` keeps the `agent-ok` label default only when no filter is given: `--milestone` or `--exclude-label` alone no longer AND with it, the rule is named after all its filters, and the effective rule is printed before the check (#474).
- Fixed: The dashboard's sidebar count for All work is the number the list shows, with the sub-tasks beside it (for example 257 and +514, with a hover title) while Child cards is off; with Child cards on every item is a card and the count has no note (#475).
- Fixed: A new work log starts at the current format, so a fresh stack's `supervise_start` launches workers with no `format_raised` by hand. A log that already has records keeps its format until a person raises it. Every refusal for the format now says which record needs which format, the log's format, and that a person raises it with `format_raised`; `supervise_status` shows it as `paused_because`, `GET /v1/me` reports each team's `log_format`, and `dev/quickstart.sh` prints it with the command to raise a log that is behind.
- Documentation: The supervise profile examples pass `USER` (macOS needs it for Claude Code's saved login) and say what to do when workers exit with "Not logged in".

## [0.2.0] - 2026-11-19

- Upgrading from 0.1.0: 0.2.0 reads every 0.1.0 log as it is. The work log format goes from 13 to 24, and nothing raises it for you. A log stays at 13 until a person posts `format_raised` (`to` up to 24; see [upgrades](docs/upgrades.md)), and a feature that needs a newer format is refused with `format` until then. Upgrade the tracker first, then ingest, `kbl-mcp` and the dashboard, and raise the format last, once no 0.1.0 build is still running: a 0.1.0 reader stops at a record above 13. The raise cannot be undone, so take a backup first. Each format's feature and its raise are in the Formats table of that page.
- Added: The item panel says what is happening now (who holds it, the attempt, last activity, claim deadline, or what it waits on), lists the log's records on the item newest first with live relative times and a folded output tail per step, shows linked work (pull request and checks, child work with its recorded answer, waits-on and blocks), and lists each attempt with its outcome, summary, summary mark and cost, linked into the decision replay. The page's fold gains `activity_json` and `hold_deadline_ms` on each item; both are read from existing records, so no record kind or format changes and no golden file changes.
- Added: The board nests triage, augment and other child work under its root with a progress chip and a toggle for child cards, leads each card with the upstream reference (`felix#1694`), shows which agent holds an item with its attempt and time since last activity, says what a blocked card waits on, and carries tier, source, pull request and assignee.
- Added: A question frees the agent (format 14). `work_ask` ends the claim without using a try and parks the item in Needs you; a
  plain answer sends the item back to Ready with the question and answer in its context. `work_release` takes `why`:
  `waits_on_person` and `waits_on_outside` use no try and park the item until a person moves it out; only failures count
  toward the two tries. An agent whose claim lapsed while it waited may still ask or release as a wait once. Every
  `work_next` reply and the `kbl-mcp` tool descriptions say questions go through `work_ask`, never the host's chat. Raise
  the format to 14 after upgrading (docs/upgrades.md); the golden `wasm/golden/format_14.jsonl` and
  `wasm/golden/format_14.state.json` pin the new fold.
- Added: A person can block an item until a time or on a named resource such as `azure-vms`, with a reason, and lift the block. `work_next` and `work_peek` skip a blocked item on every path, a time ends the block with no background job, and the card and item panel show it. Tools: `block_item` and `lift_block`; routes: `POST /v1/work/block` and `/lift-block`. This is format 16: raise it after upgrading (docs/upgrades.md). Agent requirements and ingest label mapping are not part of this change. The new golden `format_16` stores the fold result of a log that sets two blocks, lifts one and claims an item.
- Added: `work_next` takes `kinds`, `tiers`, `repo` and `exclude_roots`, and roots take turns within a tier, so repeated calls no longer return children of the same roots; work an answer made ready queues behind other roots' work. The new `work_peek` tool and `POST /v1/work/peek` list the next items in order without claiming. A filtered or turn-taking claim is made from the state, so no ready record is polled, acked or nacked for an item that was passed over. There is no label filter, because items do not carry upstream labels. Filters and turn-taking need the log raised to format 15; below it a filtered `work_next` is refused with `needs_format_15` and a lane with several roots is polled in its own order.
- Added: Related items (format 18): a soft link between two items that never holds either back, unlike a dependency. A person relates items with `POST /v1/work/relate` or the `relate_items` tool and removes it with `/v1/work/unrelate` or `unrelate_items`; both cards and the item panel show it. A triage answer may name `related` items next to `depends_on`, and the `work_triage` tool says when to use which. Raise the format to 18 after upgrading (docs/upgrades.md); the golden `wasm/golden/format_18.jsonl` and `wasm/golden/format_18.state.json` pin the new fold.
- Added: An ingest rule can set `"triage": "skip"` (with `admit`) to import issues that are already well specified straight to Ready to fix, with no triage or augment item. `kbl-ingest check` reports it ("admits straight to ready"), and the dashboard shows "triage skipped by rule <name>". The choice is recorded as an optional `triage_skipped` field on the tracker's `accepted` record; it changes no stage, so the log format is unchanged, and only the tracker may write it.
- Added: The Needs you view is an inbox: everything waiting on a person in one list, oldest first, with agent and triage questions, triage proposals, review findings and stuck items. Answer a question with a digit key or typed text, accept a proposal with a tier, or unflag and close a stuck item, all from the list. The sidebar counts each kind and filters by it. The fold's item rows also carry a proposal's reasons, dependencies and split, and the review finding an item came from.
- Added: The item panel and the Needs you inbox show a finished attempt's handoff: the agent's last note, the files and lines its recorded edits touch, the pull request with its checks and failing check, its failed steps, and Accurate and Not accurate buttons for the summary. Only records the fold accepted count, so a refused `done` or mark never shows as having happened. No new record or format.
- Added: `kbl-tool work metrics` prints the Metrics tab's numbers for a window, labelled and as JSON or CSV, from a read of `work.events` and the dashboard's own fold; it writes nothing. [docs/design/supervision-experiment.md](docs/design/supervision-experiment.md) is the protocol for the supervision experiment: hypothesis, arms, assignment, measures, sample size, threats and how results are published, including a null result.
- Added: Format 17. The Needs you inbox sorts by the log offset at which each item began waiting for its present reason, recorded in the fold as `waiting_since`, so the order is the same after a reload and a restart. A person can adjust a triage proposal's dependencies and split titles: `POST /v1/work/proposals/edit` takes `depends_on`, `split` and the `proposal` offset of the answer read, which the fold checks so an edit never lands on a newer answer, and the inbox row has an Adjust advice editor (key `3`). The raise to 17 is needed before the tracker writes it ([upgrading](docs/upgrades.md)). The state of every golden whose items wait on a person gained `waiting_since`: `every_record`, `format_2`, `format_7`, `format_10`, `format_12` and `format_14` changed, and `format_17` is new.
- Added: `kbl-tool source init --triage skip` and `dev/ingest.mjs --triage skip` write the rule's `triage: skip` option; the starter configs now carry `triage` explicitly.
- Added: An item now carries its upstream issue's labels and milestone from import, and reconcile keeps them current. Triage sets a type, area and size from a per-team vocabulary in the standing rules (a value outside it is refused), and a person can override it with `classify_item`. Ingest rules can map `milestone_tiers`, `label_types` and `label_areas`. `work_next` and `work_peek` filter by `milestone`, `labels` (any of, without regard to case), `item_type`, `area` and `size`, and the dashboard groups and shows them. This is format 19 (docs/upgrades.md). The golden `format_19` stores the fold result of a log that imports with labels, edits them, sets a vocabulary, classifies and overrides.
- Added: An item can need something only some agents have (`needs`, such as `azure`, `gpu` or `network`), set by triage (`work_triage`), a person (`classify_item`) or an intake rule (`label_needs`) from the team's vocabulary. An agent passes `capabilities` on `work_next` and `work_peek` and is handed only work whose needs it covers; skipped work spends no ready record, also across a restart. `lift_resource` (`POST /v1/work/lift-resource`) ends every block on one named resource in one record. This is format 20 (docs/upgrades.md). The new golden is `format_20` (`wasm/golden/format_20.jsonl` and `format_20.state.json`, from `core/tests/work_format_20.jsonl`), and folds that include a snapshot are dropped once because the fold revision moved.
- Added: Delegated worker identities (format 21). A supervisor's agent token registers workers with `POST /v1/work/workers`; each gets its own token, acts with the supervisor's grants under per-supervisor and per-team caps, and every record it writes names the worker and its supervisor (`sup`). Worker names are `<supervisor>-<suffix>`, so they never collide with an agent's, and a worker is bound to its supervisor's token. Stopping a worker revokes its token; revoking or removing its supervisor stops it and releases its hold at no cost to the item's tries. New golden logs: `core/tests/work_format_21.jsonl` and `wasm/golden/format_21` (`format_21.jsonl`, `format_21.state.json`).
- Added: Supervise tools in `kbl-mcp`: with `KBL_SUPERVISE_CONFIG`, an agent runs a pool of worker agents of any vendor with `supervise_start`, `supervise_stop` and `supervise_status`. Workers start from launch profiles (`kind = "command"`, an argv template run without a shell, with a per-worker MCP config in JSON or TOML written mode 600; or `kind = "hook"`, which hands a hosted agent a one-time code it trades at `POST /v1/work/workers/exchange`). A fit table picks each worker's profile and model from the item's tier, kind, type, area, size and needs, and a timer tops the pool up while ready work matches, pausing after repeated failures. A worker's `kbl-mcp` holds it to the pool's filter (`KBL_WORK_FILTER`). Example profiles for Claude Code, Codex CLI and GitHub Copilot CLI are in `docs/supervise-profiles.md`; `dev/fake-worker.mjs` is the scripted worker CI runs.
- Added: The dashboard sets and clears an item's needs (Set needs on a root's panel, `N`, or the palette), through the existing `classify_item` route. The tracker fault sweep now gives items needs and agents capabilities that change between claims, and checks that work goes only to a claimer that covers the needs. A new or changed `label_needs` mapping re-maps the rule's existing issues on the next poll, once.
- Added: The dashboard has a Workers dialog (sidebar button or palette): each supervisor with the workers it started, their state, launch fields and hold, finished and stopped workers kept, and a Stop for one worker or all of a supervisor's (`workers_json()` on the wasm fold). The supervise dev check now has its workers report `worker_finish`, so the finish path runs in CI.
- Added: Hook workers can say they are done (format 24). A hosted worker calls the `worker_finish` tool, or `POST /v1/work/workers/finish` with its own token; the tracker logs `worker_finished`, ends the worker and gives back what it holds. `supervise_status` then lists it under `finished`, drops it from the pool and the top-up replaces it. New golden logs: `core/tests/work_format_24.jsonl` and `wasm/golden/format_24` (`format_24.jsonl`, `format_24.state.json`).
- Added: A failed check on an agent's pull request becomes `fix_check` work (format 23). Ingest reports a check that stays red after any flake re-run as `check_failed`, with the end of the job's log; the tracker opens a `fix_check` child under the root that an agent claims with the log in its context and pushes to the same request. Green checks close it. After `KBL_AUTO_FIX_TRIES` (default 1) tries on the same check, the failure goes to Needs you as before, with every try's log excerpt on the root. Reading job logs needs Actions: read. New golden logs: `core/tests/work_format_23.jsonl` and `wasm/golden/format_23`.
- Added: Known flaky checks are re-run once (format 22). A person keeps a flake list (`GET`/`POST /v1/work/flakes`, `POST /v1/work/flakes/clear`); when a red check matches an entry, ingest re-runs the failed jobs through GitHub and records the check as pending, so a flake that passes on re-run never becomes work. `flake_retried` is kept on the item and each entry counts its hits. The GitHub credential needs Actions write (the `actions: write` App permission) for the re-run; without it the check goes the normal way. New golden logs: `core/tests/work_format_22.jsonl` and `wasm/golden/format_22`.
- Added: Needs you shows every failed try of a check on a root (check, head commit, the fix it opened, the job link and the log excerpt), and the dev stack now drives a red check to a claimed `fix_check` and a green head (`dev/check-tracker-fix-check.mjs`). A redo after the fix tries are spent still needs a note, now covered by a test.
- Added: The dashboard's Metrics dialog shows time in each stage (p50 and p85), items done per day and week, rework (redos, reopened, failed attempts per done item), cost per done item (per model where recorded), and supervision (items a person touched, records a person wrote, time waiting on a person) for the last 7, 30 or 90 days. The fold computes them from accepted records in `metrics_json`, so a refused record never counts and an item reopened and done again counts once. No record or format change and no golden file changes: the golden stems are untouched. See docs/flow-metrics.md.

A confirm says that a new attempt branches from that decision, that it counts against the item's redos and how many are left, and takes an optional note, required while the pull request has a failed check. The new attempt is listed with its fork point. The tracker gains `POST /v1/work/redo` and `kbl-mcp`'s person tools gain `redo_from_decision`, both writing the existing `forked_from` record, and the dashboard's item rows carry `redos_left` and `redo_pending`. No record or format changes.
- Added: The dashboard list can group by stage, tier, repo, kind or assignee, or not at all. Groups have a header button with a count and fold away; `J` and `K` skip folded groups. The grouping is in the address and in saved views, and the palette and `G` reach it. The board keeps its stage columns. No record or format change.
- Changed: Dashboard: on a phone a row keeps room for its title and its details go under it, the worker table stacks, the command palette names the kind once, and every screen is captured light and dark at 1280 and 390 px in CI (#132).
- Changed: Ingest keeps within a request budget. A worker spends half of the vendor's reported hourly limit by default (`budget_share`, or `budget_per_hour`), keeps a fifth of it for write-backs, and sends no request to a vendor that has asked it to wait (GitHub, Jira, Azure DevOps and GitLab rate limit headers and answers), up to an hour. `poll_seconds` is now a minimum and defaults to 300, and the gap stretches to fit the budget. `reconcile_every` is replaced by `reconcile_hours` (default 24): each poll re-reads its share of the open imported issues instead of all of them every few polls. `kbl-ingest check` reports the vendor's remaining budget and the projected requests an hour.
- Changed: Ingest takes its request budget from the pool. A worker that serves a connection spends its share of the budget pool set with `PUT /v1/org/budgets/{pool}`, in proportion to the sources it holds leases on, and uses the pool's kept-back and wake numbers. Webhook wakes spend a wake share inside the kept-back part and wait for the interval when it is spent. A rate limit answer is shared through `PUT /v1/ingest/backoff/{pool}` (the later time wins, capped at an hour), so one worker's refusal stops every worker in the pool. Behaviour change for existing files: `poll_seconds` below 60 now polls every 60 seconds. `budget_share` still defaults to 0.5, because GitHub counts its limit per account; a bot account or GitHub App can raise it to 0.9.
- Changed: KBL runs on Felix 0.7.2: `felix-client` is pinned at `=0.7.2` and the dev stack and quick start run the 0.7.2 control plane and broker with felix-gateway 0.9.0. The tools hold a `Connection` where they held the 0.6 `Client`; behaviour is unchanged, and the broker environment the stack sets is unchanged.

The tracker answers `GET /` (no token) with its name, version and `/healthz`. `connect.mjs`, `agents.mjs` and `ingest.mjs` also look in `~/.kbl/bin` and `dev/state/bin`. The dashboard keeps the gateway session and the person sign-in across a reload in that tab's sessionStorage, shows "Viewing (read-only)" with "Sign in to act", and the quick start prints a "view link" and a "person token for actions". An armor line whose value starts another key header now ends the armor, and the redaction reads that header as a key of its own. Records already on the log are unchanged.
- Fixed: The redaction linearity test now compares one adversarial input at two sizes and checks the time grows about 4x for 4x the bytes. It no longer fails on a slow runner.
- Fixed: The two remaining redaction linearity tests now compare each input at two sizes instead of asserting a wall-clock bound, so they no longer fail on a slow runner.
- Fixed: Recording a merge (`merge_marked`) is refused while upstream shows the request open, and the item keeps who recorded it and at which offset (`merge_marked` on the item, shown as marked merged by that person). If upstream later shows that request open or closed unmerged, the item reopens into Needs you as `merge_disputed`; an upstream merge or a reopen clears the mark. A review ask made while upstream shows changes requested now lasts until the review state changes, not until the same state repeats, and a new attempt drops any ask and send-back. The wasm golden `format_11` changes: its state now carries `merge_marked` on the item a person marked merged.
- Fixed: Ingest finishes admitting an imported root after a poll fails partway through it, and reopens a root whose close was written but whose save was lost when the issue is open again by the next poll.
- Fixed: A tracker no longer hands an agent back a claim whose hold another writer already released, as after a broker failover. Before a resumed `work_next` or an `extend` it reads the log from the end of its state and rebuilds when anything landed there, so two agents cannot work one attempt.
- Fixed: The tracker prunes snapshot files by the log they belong to, so files left from before a retention trim are removed, and a save that started before a rebuild no longer writes or prunes after it.
- Fixed: A tracker restart keeps a direct claim (one handed straight to an item's agent assignee) even when the item was reassigned while the agent held it. Before, the restart polled the ready lanes for it, which spent a Felix handout on other items' head records, and then released it as lapsed before the deadline the agent was given, so a new assignee could start a second attempt while the old holder still worked. The tracker now records whether each claim was direct, keeps such a hold for one visibility period from the restart, and polls nothing for it. Snapshots from earlier builds are not read; the tracker folds the log instead.

  The dashboard's assign picker lists the team's agents beside people, from the new person route `GET /v1/work/agents` (agents not revoked), and assigns with `{"agent": name}`.
- Fixed: An Azure DevOps listing that hits its 2000-item cap inside one change instant now resumes after the last id read, so the cursor no longer stalls on the same items.
  A refused Azure DevOps state change is dropped only when the process names a rule or transition error; other failures are retried.
- Fixed: The GitLab source no longer skips an issue that is updated while its project is being read: each request restarts from the last time seen instead of paging by number. It reads times with a UTC offset (`+01:00`) instead of treating them as unknown, and a GitLab root now shows its repo in the work views.
- Fixed: Jira: a failed rule search stalls the project instead of dropping issues from scope, a `jql` with `ORDER BY` is refused, and the worker refuses to start when it cannot learn its own name.
- Fixed: A failed run log write is counted by the next write that lands, a record that is not a task is logged by its group offset when dead-lettered, and `task_claim_lost` says whether Felix refused the extension with `stale_claim` or none worked for a visibility window. The gap count is kept in memory, so it is reported only if that `kbl-mcp` process logs again.
