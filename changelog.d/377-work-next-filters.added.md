`work_next` takes `kinds`, `tiers`, `repo` and `exclude_roots`, and roots take turns within a tier, so repeated calls no longer return children of the same roots; work an answer made ready queues behind other roots' work. The new `work_peek` tool and `POST /v1/work/peek` list the next items in order without claiming. A filtered or turn-taking claim is made from the state, so no ready record is polled, acked or nacked for an item that was passed over. There is no label filter, because items do not carry upstream labels.
