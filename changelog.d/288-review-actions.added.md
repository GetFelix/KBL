A person can request a review, send a pull request back for changes, record a merge and mark an agent's summary accurate or not over REST: `POST /v1/work/request-review` (`{item, reviewer}`), `/request-changes`, `/mark-merged` and `/rate-summary` (`{item, attempt, accurate}`), with new records `review_requested`, `changes_requested`, `merge_marked` and `summary_rated`. They are format 11: the tracker refuses them until a person raises each team's log to 11 (`format_raised`, see docs/upgrades.md), after every tracker and dashboard page reading that log is this build or newer. The ask and the send-back sit beside upstream's `pr_status` and drop when upstream answers or the request ends; a recorded merge closes the item as merged; the latest summary mark per attempt stands.
The dashboard's Story section shows each finished attempt's summary mark with Accurate and Not accurate buttons. The name `summary_rated` is now a known record kind: an old unversioned `summary_rated` line no longer decodes as unknown. The wasm goldens `format_10` and `format_11` pin the new records and the state they fold to.
