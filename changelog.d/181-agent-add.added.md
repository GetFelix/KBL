`kbl-tool agent add <name>` mints a tracker token for a new agent, one per `kbl-mcp` session, and the tracker accepts it on the next call with no restart. `agent list` shows each agent and what it holds, and `agent revoke` stops the token and releases the agent's holds with the reason `revoked`, as a lapsed claim is. The routes are `POST`, `GET` and `DELETE /v1/teams/{team}/agents`, for org admins, with teams on. Only the token's SHA-256 is kept, on `org.events`.
A team holds at most 256 live agents; a revoked agent frees its place but not its name. While a tracker does not hold the org lease it answers `503` with `org_unavailable` to agent tokens added this way, and it rereads `org.events` when it takes the lease back, so a revoke written meanwhile holds. The tracker refuses to start while its token file names an agent `agent add` minted and nobody revoked.
