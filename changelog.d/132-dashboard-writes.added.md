The dashboard writes: a person signed in with their own tracker token can accept, reject, set the tier of, close and answer items through the tracker's person routes, from the panel or in bulk (`X` marks an item, each list row has a checkbox). Each write shows as pending, written or refused with the tracker's reason. A tier change can be undone (`Mod+Z`) with a new `tier_changed` record; the writes the log cannot take back ask to confirm first. A Needs you view (`?view=inbox`) lists what waits on a person and why, and an open question shows its text, options and default. The page calls only its own origin's `/v1` routes (`npm run dev` forwards them to `KBL_TRACKER_URL`). The WebAssembly fold's item list now carries each item's `needs`, open question offset, options and default, and whether it is a root.
