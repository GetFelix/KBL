`kbl-ingest check` now tests Azure DevOps and GitLab configs instead of only validating them. It signs in, reports the permissions each rule needs (project read, work item edit, the GitLab `api` scope and role, token scopes and expiry), and dry-runs the first poll the way the worker selects it. Everything it sends is a read; for Azure DevOps the one allowed POST is the work item query.
